Arquivo ZIP · código-fonte · sem senhas ou arquivo .env

Erro 403 no link antigo? Use esta página dentro da prévia atual na plataforma. Primeiro clique em Preparar arquivo ZIP; depois, em Salvar ZIP no computador. Não é preciso abrir outro domínio.
Importante: este site não é estático. Não arraste o ZIP para Cloudflare Pages. O Admin, as pautas, os uploads e os PDFs precisam de Workers + PostgreSQL. Não é necessário manter um segundo servidor Node.
Alternativa mais prática

Publicar sem baixar o ZIP

Se a plataforma bloquear o arquivo, não precisa clicar repetidamente. Abra o Admin e clique em Publicar sem ZIP. O portal pode enviar os arquivos diretamente ao seu repositório GitHub, usando sua autorização temporária com permissão Contents: Read and write.

O token não é salvo no banco e deve ser inserido somente no formulário do portal, nunca na conversa. Use um repositório privado novo ou dedicado. Depois da confirmação do GitHub, continue abaixo na etapa de conectar o repositório ao Cloudflare.

Abrir o Admin e publicar sem ZIP

Esse envio não publica o site sozinho. São necessários o deploy na sua conta Cloudflare e o banco PostgreSQL de produção. Sem autorização dessas contas não há como gerar um link público permanente por aqui.

1

Baixe e extraia o arquivo

Clique em Preparar arquivo ZIP acima. Quando o botão mudar, clique em Salvar ZIP no computador. Depois, escolha Extrair tudo no computador. Abra a pasta your-magazine. Ela deve conter package.json, wrangler.toml, src e public.

O arquivo LEIA-ME-CLOUDFLARE.md, dentro do ZIP, contém este guia e informações técnicas adicionais.

2

Crie o banco de dados

Recomendo Neon: crie um projeto PostgreSQL, abra Connect e copie a connection string com SSL.

Você também pode usar o PostgreSQL do Supabase. Nesse caso, copie a conexão do banco/pooler, não a chave pública da API.

Não use 127.0.0.1 ou localhost: esse banco só existe dentro do preview. Use um banco novo, público e dedicado ao portal.
3

Coloque os arquivos no GitHub

  1. Crie um repositório privado chamado your-magazine em github.com.
  2. Em Add file → Upload files, envie o conteúdo da pasta extraída, não o ZIP.
  3. Confirme que package.json está na raiz do repositório.
  4. Se o GitHub limitar a quantidade de arquivos do upload web, envie em etapas ou use o GitHub Desktop.
  5. Não envie arquivos .env nem pastas node_modules e .next.
4

Conecte o repositório ao Cloudflare

  1. No painel Cloudflare, vá em Workers & Pages → Create application → Connect Git / Import repository.
  2. Escolha GitHub e selecione seu repositório.
  3. Escolha Workers, com o nome your-magazine, branch main e diretório raiz em branco.
  4. Preencha os dois comandos abaixo e confirme o deploy.

Build command

node scripts/cloudflare.mjs build

Deploy command

node scripts/cloudflare.mjs deploy

Se houver um campo de instalação: npm ci. Em variáveis de build, use NODE_VERSION = 22. Normalmente o Cloudflare instala as dependências automaticamente pelo package-lock.json.

O build cria .open-next/worker.js. Usar apenas npm run build não gera o Worker.

5

Cadastre os segredos do Worker

Abra Workers & Pages → your-magazine → Settings → Variables and Secrets. Adicione os dois como Secret:

Nome exatoO que preencher
DATABASE_URLA connection string PostgreSQL pública com SSL do passo 2.
ADMIN_PASSWORDA senha que você definiu para o painel Admin.

Salve e confirme Deploy / Save and deploy, caso o painel solicite. Essas são variáveis de execução: não basta adicioná-las somente em Build variables.

Não adicione o prefixo NEXT_PUBLIC_. Não cole credenciais no GitHub.

6

Confira o site publicado

O Cloudflare vai mostrar uma URL https://your-magazine.SEU-SUBDOMINIO.workers.dev. Abra-a em uma aba própria e teste:

  • /api/health: deve responder {"ok":true}.
  • /pt: o conteúdo inicial é criado no primeiro acesso; ele pode demorar mais.
  • /admin: entre com a senha cadastrada em ADMIN_PASSWORD.
  • Altere um texto, recarregue e confirme que persistiu.
  • Envie uma pauta e confira em Admin → Central de Pautas.
  • Teste uma imagem enviada e um PDF.

Se houver erro, veja Observability / Logs no Worker e confira os segredos. O banco remoto não foi criado na sua conta por este pacote.

7

Adicione seu domínio

  1. Adicione seu domínio à conta Cloudflare e conclua a alteração dos nameservers, se necessário.
  2. No Worker, vá em Settings → Domains & Routes → Add → Custom Domain.
  3. Digite seu domínio, confirme e aguarde o certificado HTTPS.
  4. Se quiser, repita para www.
  5. Só remova a publicação antiga depois de testar tudo no endereço novo.

Para esse portal dinâmico, considere o plano Workers Paid. Consulte os limites e preços atuais.

O que está — e não está — no ZIP

Incluído: código-fonte, matérias e catálogo iniciais, imagens oficiais e configurações de publicação.

Não incluído: senhas, tokens, banco do preview, pautas privadas recebidas e anexos enviados ao banco. Se deseja levar as alterações exclusivas do banco atual, faça uma migração PostgreSQL separada para o banco de produção.

O portal preserva o conteúdo já cadastrado em um banco existente. Atualizar o código não redefine suas edições.
